# 刷在线课程 / 完成学时

把"刷课"当成一个**逆向平台计分规则**的问题，不是"点播放然后等"的问题。

核心结论先给，这四条是整个流程的成败点：

1. **完成线是视频的 80%，但进度只在视频播到结尾时才上报。** 停在 80% 记录为 0。
   这是最反直觉、最容易白刷一整门课的一条。
2. **倍速上限是播放器自带档位（通常是 1.5x）。** 4x 加回拖进度条会触发"学习异常"警告。
3. **文档类课程不是"要读"，而是"停留满几秒自动完成"。** 页面上的 `需学 00:05` 就是阈值。
4. **页面显示的"课程进度 0%"经常是缓存。** 判定完成一律以接口为准。

## 先判断是哪一类内容

打开课程后看章节行右侧：

| 页面显示 | 类型 | 完成条件 |
| --- | --- | --- |
| `视频 34:43 需学 27:47` | 视频 | 播放到**视频结尾**（34:43 × 80% = 27:47 就是那条 80% 线） |
| `文档 05:00 需学 00:05` | 文档 | 打开后**停留约 5 秒**，翻页/滚动即可触发上报 |

`需学` 后面的数字是"还差多久达标"，不是"要学多久"。视频类它等于该视频 80% 位置；文档类它基本是平台的最小停留阈值。

## 工作流

### 0. 接管浏览器

**先确认登录态在哪个浏览器里。** 这一步最容易走错：

```bash
# 浏览器必须带调试端口启动，否则接管不了
curl -s http://127.0.0.1:9333/json/version
```

Chrome 136+ **拒绝**对默认 user-data-dir 开放 `--remote-debugging-port`。所以日常在用的 Chrome 通常没有可用端口，无论它启动时加没加参数。两条路：

- **推荐**：另起一个带独立 profile 和调试端口的实例，在里面登录一次，之后长期复用。独立 profile 不受该限制。
- 或走 GUI 自动化（cua-driver）直接操作用户自己的窗口。

> 接管别人的浏览器前先问清楚：能不能开新实例、是否需要保留当前登录态。

### 1. 摸清上报接口（换平台必做）

在未知平台上，**不要凭页面文字猜规则**。跑探测脚本，然后自己在页面上点几下：

```bash
node scripts/probe-api.mjs 180 progress
```

它把进度请求的 URL、鉴权头、请求体和响应全打出来。你要从里面读出三件事：

- 哪个接口携带进度；
- "完成"的判据是什么（百分比规则？秒数阈值？）；
- **什么动作才真正触发上报**。

第三点最关键。本次实测就发现：只有视频播到结尾才上报。

### 2. 列出未完成项

```bash
node scripts/list-courses.mjs <subjectId>
```

`subjectId` 是 URL `#/study/subject/detail/<subjectId>` 里的 UUID。输出剩余课程及其 `courseId`。

### 3. 逐门完成

**一次只开一门。** 批量打开课程正是平台判定异常学习的行为：

```bash
node scripts/open-course.mjs <courseId> <subjectId>   # 打开并确认章节结构
node scripts/play-course.mjs <courseId>               # 逐章播到结尾
node scripts/list-courses.mjs <subjectId>             # 复核（不要只看页面）
```

视频章节会以 1.5x 播到结尾；文档章节只做停留。脚本每次只处理当前打开的那一门。

**整专题批量刷**用 `run-subject.mjs`，它把上面这套串起来，并且是断点续跑、可中断、能自愈的：

```bash
node scripts/run-subject.mjs <subjectId>
```

它每轮都重新从服务端读进度，所以中途被杀掉（宿主重启、休眠、token 过期）后**直接重跑即可**，不会重复刷已完成的课。一个新专题建议先用 `open-course.mjs` + `play-course.mjs` 手动验证一门，确认规则一致后再交给它跑。

### 4. 复核

**始终以 `list-courses.mjs` 为准**，不要相信页面上的百分比。本次实测中，页面刷新后仍显示 75%，而服务端该课程 4 个章节已全部 `finishStatus=2`。

## 红线

这些不是建议，是踩过的事故：

- **不要超过播放器自带的最大倍速。** 1.5x 正常计学时；4x 会触发警告。
- **不要回拖进度条。** 结合高倍速使用会直接触发风控。
- **不要批量打开课程。** 平台明确警告过。
- **不要在风控警告出现后继续硬刷。** 走「恢复流程」。
- **不要为了"省时间"跳到 80% 就切章。** 那一步不产生任何记录。

需要说明的是：这类自动化通常不符合平台的学习协议，属于用户自己承担后果的操作。**默认按"保住账号、不触发风控"来做，而不是按"最快刷完"来做**；如果用户要求更激进的提速方式，先说明风险再让其决定。

## 风控警告与恢复

出现「您当前的学习出现异常，请切换章节，重新进入后再学习一下」时：

1. **立即停止当前脚本。**
2. 点掉弹窗的「我知道了」。
3. **切到另一个章节**（警告文案本身就是这么要求的），让会话重新开始。
4. 换回正常速度（≤1.5x）继续。

**影响范围**：账号不受影响，不掉线、不扣分、不封号；损失的是**警告期间那段未上报的播放时间**，需要重播补上。

判断影响面时，记得先看服务端已有记录，不要被弹窗文案吓到：

```bash
node scripts/list-courses.mjs <subjectId> --json
```

## 常见故障

**`Access is Denied` / HTTP 401**
会话 token 过期了，不是请求写错。**刷新一次页面**让前端换取新 token，再重试。长时间运行的脚本必然会遇到，属于正常现象。

**点击课程没反应**
专题列表是虚拟列表，滚出视口的行会被回收，缓存的 locator 指向已被回收的元素。必须先 `scrollIntoView`、再重新读取按钮坐标、然后才点。`open-course.mjs` 已按这个顺序实现。

**脚本报点了按钮但状态没变**
合成事件（`element.click()`）对 Vue/React 绑定的处理器无效，只有元素中心点的**真实鼠标事件**才生效。统一使用 `cdp.mjs` 里的 `realClick`。

**视频播完但进度仍是 0%**
等约 60 秒再查。进度上报是周期性的，且常在播放结束时才提交一次。

**"新标签页"抓错**
用 `!before.has(url)` 判断新开的课程页并不可靠：浏览器里常有历史遗留标签页，脚本会抓到错的那个，然后把打开成功的课程误判为失败。**认 URL 形态而不是"是否新"**——直接找 `/study/course/detail`。

**课程页打开了但章节数是 0**
章节列表和 `<video>` 都是异步挂载的。固定延时后只读一次必然踩空，结果是整门课被跳过、一学时都不计。必须轮询等待（见「异步挂载」一节）。

**跑到一半报 `Target page, context or browser has been closed`**
页面或浏览器被关掉了（用户手动关、休眠、宿主进程重启）。脚本若继续使用失效的 page 引用，会一路抛错直到进程崩溃。**每轮开头重新 attach 并探测页面是否可用**，失效就重连，不要让异常冒泡出去。

**播了很久但学时几乎没涨**
浏览器休眠或标签被冻结时 `currentTime` 会停止前进，页面也随之停止上报。**要监控 `currentTime` 是否推进**：超过 2 分钟没动就重新 `bringToFront()` 并恢复播放。没有这个检测，脚本会安静地空等几小时。

## 异步挂载：为什么必须轮询

这是实测踩出来的，两处都栽过：

- **`<video>`**：课程页打开后约 3 秒才出现。固定延时检测一次，会把视频课误判成文档课并"跳过"，**一学时都不计却报告成功**。
- **章节列表**（`.chapter-item`）：同理，读早了就是 0，整门课被跳过。

统一做法：给一个上限（30–35 秒），每秒轮询一次，拿到有效值再继续。不要"睡 N 秒后读一次"。

## 长跑任务的健壮性

一次刷十几门课要跑几小时，脚本必须能扛住中断：

- **断点续跑**：每轮开头重新拉一次服务端进度，只处理仍未完成的。中断后重跑即可，不要试图在内存里记进度。
- **单门失败不能拖垮整轮**，失败项下轮重试。
- **一门课播完、等上报落地后**再处理下一门。
- **宿主进程重启会杀掉子进程**。所以进度只认服务端接口，别信日志——日志可能停在任意位置。

## 平台细节

智学云 / 知识中心的接口封装在 `scripts/zhixueyun.mjs`，已在真实账号上验证，包括两个容易踩的点：

- 鉴权头是 `Bearer__<token>`（**两个下划线**）。写成标准的 `Bearer <token>` 会 401。
- 进度接口需要 `Version: 12.1.1` 之类的客户端版本头。

**换平台时**：不要改这几个接口地址，而是照 `zhixueyun.mjs` 的形态写一个新的适配模块。先用 `probe-api.mjs` 把新平台的接口摸清，再落代码。

**入口页可能只是跳板，真正的课程在别处。**
遇到过这种情况：一个第三方站点（如 `cms.mylearning.cn`）只是专题入口页，页面上每个培训项都链到智学云。这类页面上的链接常常伪装成手机扫码地址：

```html
<a href="https://kc.zhixueyun.com/app/wechat/#/qrScan?businessType=2&businessId=<UUID>&isThirdUrl=1">
```

**别被 `qrScan` 骗了**——`businessType=2` 是"专题"，`businessId` 就是 `subjectId`，直接在桌面端打开即可，不需要扫码：

```
https://kc.zhixueyun.com/#/study/subject/detail/<businessId>
```

判断方法：读链接里有没有 `businessType`/`businessId`；有，就把它当专题 ID 试开一次。这比在入口页上折腾点击靠谱得多，也避免了"入口页点了没反应"的假象。

## 凭据与隐私

这个技能**不存储任何凭据**，脚本里也不应出现登录态。严格遵守：

- **token 一律在运行时从页面读取**（`localStorage` / cookie），通过 `readToken()` 之类的函数取用，不要写进代码、注释或配置。
- **不要把 token、Cookie、账号、姓名、单位、课程 ID 等真实数据写进本技能。** 课程 ID 之类的标识符一旦硬编码就失去了通用性，换个人就不能用了。
- **调试输出必须脱敏。** `probe-api.mjs` 对鉴权头只打印协议前缀（如 `Bearer__<redacted>`），因为这类输出经常被贴进 issue 或分享给别人。新增日志时沿用这个做法。
- 探测脚本会打印请求体。如果某个平台的请求体里含明文凭据，先改成脱敏再运行。

提交或分享本技能前自查一遍：

```bash
grep -rniE "bearer|token|cookie|password|secret" --include="*.mjs" --include="*.md" .
grep -rnoE "\b[0-9a-f]{24,}\b" .   # 长十六进制串通常是 token
```
